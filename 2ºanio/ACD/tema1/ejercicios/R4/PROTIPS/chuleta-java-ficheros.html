Acceso a Datos · 2.º DAM · Bloques probados para cada operación (copiar y adaptar) y todo el temario de la UD1 con buscador

Plantillas

i Cómo usar estos bloques

  1. Busca el método con TODO que te piden (cargar, buscar, eliminar…) y su bloque aquí.
  2. Pulsa Copiar y pega el cuerpo dentro del método del ejercicio (la firma ya te la dan).
  3. Cambia los nombres: Producto → la clase del ejercicio (Inscripcion, Equipo…), getCantidad → su getter, "productos" → sus etiquetas…
  4. Si el ejercicio ya te da un método (por ejemplo esValida, guardarTodo, crearCopiaSiExiste), usa el suyo en vez de copiar el mío.
  5. En el gestor/repositorio: sin System.out. Devuelve true/false, null o lanza IOException; los mensajes van en Main.

Todos los bloques usan esta clase de ejemplo: Producto(int id, String nombre, int cantidad), y el CSV id;nombre;cantidad.

Ejercicio de repaso 1 · Relación 2

B1 Cargar CSV (leer y validar todo)

Qué hace: Lee el CSV, comprueba la cabecera, convierte cada línea en objeto y la valida. Si una línea está mal, lanza IOException.

Devuelve: La lista de objetos (vacía si el archivo no existe)

Qué hace: Recorre la lista y devuelve el que tenga ese ID.

B5 Alta (añadir uno nuevo)

Qué hace: Carga, valida, comprueba que el ID no exista, añade, hace copia y guarda.

Devuelve: true si se añadió, false si no

Para adaptarlo cambia:

B6 Modificar un campo

Qué hace: Comprueba el valor, busca el ID, cambia solo ese objeto, hace copia y guarda.

Devuelve: true si se cambió, false si no existe o el valor no vale

Para adaptarlo cambia:

  • La comprobación del valor (cantidad < 0)
  • El setter (setCantidad)

B6b Modificar dos campos (o un campo sin setter)

Qué hace: Cambia el nombre y la cantidad a la vez. Como no siempre hay setter (o no puedes tocar la clase), crea un objeto nuevo con los datos cambiados y lo pone en el sitio del viejo. Valida antes de guardar.

Devuelve: true si se cambió, false si no existe o los datos no valen

Para adaptarlo cambia:

  • Los parámetros nuevos y el new Producto(...) (campos que se mantienen → del objeto viejo con su getter)
  • Haz un método NUEVO; no cambies la firma del que te dan

Si la clase SÍ tiene setters y te dejan usarlos: en el paso 3 haz viejo.setNombre(nombre); y viejo.setCantidad(cantidad);, valida viejo y te saltas el paso 5.

B7 Eliminar por ID

Qué hace: Construye una lista nueva sin ese ID. Si no estaba, no guarda nada.

Devuelve: true si se borró, false si no existía

Para adaptarlo cambia:

  • Nombres de clase y métodos

B8 Crear copia de seguridad (.bak)

Qué hace: Copia archivo a archivo.bak. Llámalo justo antes de guardar.

Devuelve: Nada

Para adaptarlo cambia:

B9 Restaurar la copia

Qué hace: Copia el .bak encima del archivo. La pregunta S/N va en Main (bloque F7).

Devuelve: true si se restauró, false si no hay copia

Para adaptarlo cambia:

H · Excepciones

Convertir errores en IOException

H1 Convertir excepciones

Qué hace: Cuando el método solo puede lanzar IOException pero dentro salta otra.

Cambios típicos

0 Antes de tocar nada (5 minutos)

  1. Ejecuta el programa tal cual y prueba cada opción. Así sabes qué hace y si ya funciona.
  2. Mira qué clases hay y quién usa a quién: la clase de datos (Producto, Club…), el repositorio, el Main/menú.
  3. Busca dónde se lee y dónde se escribe cada fichero: Ctrl+Shift+F y busca Files., split, createElement, mapper.
  4. Después de cada cambio, compila y ejecuta. No hagas diez cambios seguidos.

⇄ Cambiar de clase (Producto → Club, Préstamo…)

  1. F2 sobre el nombre de la clase → escribe el nuevo. Cambia la clase, el fichero y todos los usos.
  2. Cambia los atributos (ver «Añadir/Quitar un campo»). Ojo con los tipos: double precio → String ciudad implica quitar Double.parseDouble y validaciones de «negativo».
  3. Renombra también variables y textos: productos → clubes, etiquetas XML "producto" → "club", mensajes, rutas (productos.dat).
  4. Si cambias el tipo de un campo, revisa parseInt/parseDouble en lectura de CSV y XML.

¿Por qué en un TXT hay que reescribir todo para modificar? Porque las líneas tienen longitud variable: cambiar «Cádiz» por «Villanueva de la Serena» ocupa más bytes y pisaría el registro siguiente.

✓ Reglas de oro del temario

  • Indica siempre UTF-8.
  • Comprueba que el fichero existe antes de leerlo.
  • Si buscas y no encuentras, no reescribas el fichero.
  • Haz una copia antes de sobrescribir y pide confirmación antes de restaurar o borrar.
  • Al importar, valida todo en una lista temporal y solo después sustituye los datos.
  • Un registro defectuoso no debe hacer perder los válidos.
  • No construyas XML ni JSON concatenando cadenas: usa la API.
  • No deserialices ficheros de origen desconocido.

⌕ Leer un error

Fallos típicos

⚠ Resetear el booleano dentro del bucle

⚠ Apartar las líneas buenas en vez de las malas

if (campos.length == 3) { add; continue; } salta las buenas antes de compararlas. Lo correcto es != 3.

⚠ Añadir dos veces la misma línea

Cada línea debe entrar en la lista una vez: o por el if o por el else. Tras un add de una línea mala, continue.

⚠ add antes de contains en el Set

Si apuntas el ID y luego preguntas si está, siempre dirá que sí. Primero contains, después add (o directamente if (!set.add(id))).

⚠ Cambiar una variable y añadir la línea original

stock = nuevo; lista.add(linea); → guarda el stock viejo. Hay que montar la línea nueva: c[0] + ";" + c[1] + ";" + nuevo.

⚠ APPEND al reescribir

Para modificar o borrar, si escribes la lista con APPEND, el fichero se duplica (6 + 6 líneas).

⚠ Escribir aunque no se encontró / sobre la entrada

Files.write dentro de if (encontrado). Al filtrar, escribir en un fichero nuevo.

⚠ Usar campos antes de contarlos

Comprueba campos.length antes de leer campos[1] o campos[2].

⚠ Comparar textos con ==

Lo mismo con Integer == Integer (objetos): usa int o .equals.

⚠ trim solo en un lado

nuevo.trim().equalsIgnoreCase(delFichero.trim()).

⚠ Validar pero no parar

Un if que muestra el error sin return/continue deja seguir al programa con datos malos.

⚠ isBlank no limpia

isBlank() pregunta; trim() limpia. Guarda los textos con trim().

⚠ catch vacío

Un catch sin nada esconde el error: el programa parece que funciona. Pon al menos un mensaje.

⚠ return en main dentro de un menú

Cierra el programa entero. Mete cada opción en un método.

⚠ Rutas absolutas o con \\

Solo funcionan en tu equipo. Usa Path.of("datos", "x.csv").

⚠ Sustituir los datos durante una importación

Valida todo en una lista temporal; si algo falla, los datos anteriores no se tocan.
